# Project structure

## Top level

| Path | Contents |
|---|---|
| `annotations/` | Exported Ghidra state and the decompiled tree — see below |
| `cmake/` | Toolchain files, source collection, bundled-library builds, skip list |
| `contracts/` | GBNF grammars constraining LLM-assisted output |
| `docs/` | This directory — how the project is built and worked on |
| `headers/` | Watcom C/C++ 11.0 standard library headers, for typing the original |
| `historical_annotations/` | Archived annotation exports, for tracking analysis over time |
| `promptlib/` | Reusable prompt fragments (`core/`, `debug/`, `recipes/`, `tasks/`) |
| `prompts/` | Task prompts — `fix_compilation.md` is the authority on `.keep` rules |
| `research/` | Investigations and findings — see [research/README.md](../research/README.md) |
| `scripts/` | Bash and Python automation |
| `spec/` | Custom Ghidra processor specs for Watcom x86 |

Game data (`*.POD`, `BACKDROP/`, `MODELS/`, the executables) is **not** in the repository — it
is gitignored, and the build never requires it.

## `annotations/<binary>/`

The project analyses three binaries: `nocedit.exe` (the level editor, and the one that builds
and runs), `nocturne.exe` (the retail game, imported as a sibling for comparison), and
`tridx7.dll` (the DirectX 7 renderer).

| Path | Contents |
|---|---|
| `pseudocode/src/` | The decompiled tree, one directory per original source file |
| `pseudocode/include/` | Generated headers — types, classes, globals. **Do not hand-edit** |
| `pseudocode/shims/` | Hand-written compatibility layer — see [shims.md](shims.md) |
| `pseudocode/main/` | Hand-written entry point replacing the decompiled `entry/` |
| `pseudocode/checks/` | Generated struct-layout assertions, guarded to the 32-bit lane |
| `reports/` | Progress SVGs and per-file breakdowns |
| `*.json` | Data types, symbols, function signatures, imports |

`include/` is regenerated by `scripts/Python/headers.py`. A wrong field type or size is fixed in
Ghidra and re-exported, never by editing the header.

## Inside a function directory

`pseudocode/src/<module>/<file>.cpp/` holds one set of files per function:

| File | Role |
|---|---|
| `<name>_FUN_<addr>.cpp` | Raw Ghidra output. **Never edited** |
| `<name>_FUN_<addr>.keep.cpp` | Manual reconstruction. Compiled in preference to the raw file |
| `<name>_FUN_<addr>.asm` | Disassembly — the ground truth when the decompile is ambiguous |
| `<name>_FUN_<addr>.pcode` | Ghidra P-code |
| `<name>_FUN_<addr>.json` | Signature, address range, suspects, metadata |
| `<name>_FUN_<addr>.mmx.cpp` | Reference capture of MMX/asm intent. Never compiled |
| `<name>_FUN_<addr>.byval.cpp` | Reference capture of Watcom by-value struct passing. Never compiled |
| `<name>_FUN_<addr>.chunked.cpp` | Large functions split for readability. Never compiled |

## `scripts/`

`scripts/Bash/` — the day-to-day loop:

| Script | Purpose |
|---|---|
| `prepare_keep.sh` | Create a `.keep` from the raw output with the correct header. Always use this |
| `test_compilation.sh` | Compile one or more files standalone; also reports unused locals |
| `test_suspects.sh` | Run the source-side suspect detectors against a file |
| `dbg.sh` | Drive a gdb session in tmux — see [debugging.md](debugging.md) |
| `netplay_test.sh` | Two-instance netplay harness |
| `generate_keep_files.sh` | Bulk `.keep` preparation |
| `regen_struct_layout_checks.sh` | Regenerate the struct-layout assertions |

`scripts/Python/` — Ghidra automation (PyGhidra headless) and analysis: annotation import/export,
pseudocode export with suspect detection, report/SVG generation, hidden-function discovery,
function-boundary validation, and the sibling-binary mapping pipeline.

## Build outputs

`build/<preset>/` per preset, each with a generated `run.sh` and `debug.sh`. Build directories
are gitignored.
