# Project structure

## Top level

| Path | Contents |
|---|---|
| `annotations/` | Exported Ghidra state and the decompiled tree — see below |
| `cmake/` | Toolchain files, source collection, bundled-library builds, skip list |
| `docs/` | This directory — how the project is built and worked on |
| `headers/` | Watcom C/C++ 11.0 standard library headers, for typing the original |
| `historical_annotations/` | Archived annotation exports, for tracking analysis over time |
| `recreation/` | The clean C++ recreation of the game, with the decompiled tree as its reference — see below |
| `research/` | Investigations and findings — see [research/README.md](../research/README.md) |
| `scripts/` | Bash and Python automation |
| `spec/` | Custom Ghidra processor specs for Watcom x86 |

Game data (`*.POD`, `BACKDROP/`, `MODELS/`, the executables) is **not** in the repository — it
is gitignored, and the build never requires it.

## `annotations/<binary>/`

The project analyses three binaries: `nocedit.exe` (the level editor, and the one that builds
and runs), `nocturne.exe` (the retail game, imported as a sibling for comparison), and
`tridx7.dll` (the DirectX 7 renderer).

| Path | Contents |
|---|---|
| `pseudocode/src/` | The decompiled tree, one directory per original source file |
| `pseudocode/include/` | Generated headers — types, classes, globals. **Do not hand-edit** |
| `pseudocode/shims/` | Hand-written compatibility layer — see [shims.md](shims.md) |
| `pseudocode/main/` | Hand-written entry point replacing the decompiled `entry/` |
| `pseudocode/checks/` | Generated struct-layout assertions, guarded to the 32-bit lane |
| `reports/` | Progress SVGs and per-file breakdowns |
| `recreation/` | Input for the recreation scaffold: types, functions with callers, vtables, array descriptors |
| `*.json` | Data types, symbols, function signatures, imports |

`include/` is regenerated by `scripts/Python/headers.py`. A wrong field type or size is fixed in
Ghidra and re-exported, never by editing the header.

## Inside a function directory

`pseudocode/src/<module>/<file>.cpp/` holds one set of files per function:

| File | Role |
|---|---|
| `<name>_FUN_<addr>.cpp` | Raw Ghidra output. **Never edited** |
| `<name>_FUN_<addr>.keep.cpp` | Manual reconstruction. Compiled in preference to the raw file |
| `<name>_FUN_<addr>.asm` | Disassembly — the ground truth when the decompile is ambiguous |
| `<name>_FUN_<addr>.pcode` | Ghidra P-code |
| `<name>_FUN_<addr>.json` | Signature, address range, suspects, metadata |
| `<name>_FUN_<addr>.mmx.cpp` | Reference capture of MMX/asm intent. Never compiled |
| `<name>_FUN_<addr>.byval.cpp` | Reference capture of Watcom by-value struct passing. Never compiled |
| `<name>_FUN_<addr>.chunked.cpp` | Large functions split for readability. Never compiled |

## `recreation/`

A standalone CMake project that rebuilds the game as clean C++. It does not include, link or
copy from `annotations/`. It keeps the original structure: one directory per original
translation unit (`core/actor/`), one header per class, and the original class and function
names. Shared math lives in `common/`. Each module has a `fwd.h`, and module dependencies run one
way: `core` → `engine` → `platform` → `common`.

Game code never calls the OS. It talks to the interfaces in `platform/` (`IClock`, `IWindow`,
`IDisplay`, `IRenderer`, `IAudioDevice`, `INetwork` and the rest), which the SDL adapters
implement. Where the original already had an abstract base over OS code, that base is the seam
instead: `engine::CFont`, created through `IFontFactory` when the message list selects an OS font.
Sound keeps the game's API, sample loading and 3D math; miniaudio mixes, resamples and decodes,
and `IAudioDevice` pulls the mix as it plays.

| Path | Contents |
|---|---|
| `<module>/<tu>/` | Class headers and the TU's free-function header |
| `<module>/fwd.h` | Forward declarations and opaque enums for the module |
| `platform/` | Hand-written OS interfaces; the scaffold never writes here |
| `platform/sdl/` | The adapters behind those interfaces (`CSdlWindow` implements `IWindow`). The only code that includes SDL or OS headers; they hold no logic, and build only with `NOCTURNE_RECREATION_GAME` into `nocturne_platform_sdl` |
| `main.cpp` | The `nocturne` executable: constructs the adapters and runs the loop |
| `common/serial/` | `CBinaryReader` / `CBinaryWriter`: every file and wire format is read and written through these, little-endian with explicit widths |
| `common/input/`, `common/text/`, `common/net/`, `common/video/` | What the adapters would otherwise compute, to the Win32 behaviour the original saw: the HID-to-set-1 scancode table and `WM_CHAR` control characters, the FindFirstFile wildcard match, UTF-8 to Windows-1252, IPv4 address bytes, the framebuffer formats and 8-bit palette expansion, and the letterbox with its mouse mapping |
| `tests/mocks/` | gMock implementations of the platform interfaces and seam factories, shared by all tests |
| `tests/` | GoogleTest tests, mirroring the source paths |
| `cmake/coverage.cmake` | The coverage gate |
| `coverage_exclusions.txt` | The only paths exempt from coverage, one reason per line |

The public API is generated by `scripts/Python/scaffold_recreation.py` from the `recreation`
export category, and never overwrites an existing file without `--force`. Its
`PLATFORM_BOUNDARY` table names every original that is not recreated as game code and where its
job went; the report lists them. `--prune` removes generated headers and tests the scaffold no
longer plans. Build it on its own with
`cmake --preset default` and `cmake --build --preset default` inside `recreation/`. The targets
`format-check` and `tidy` run clang-format and clang-tidy. The `coverage` preset's `coverage`
target runs the tests and fails below 100% line, function or branch coverage. The `game` preset
also fetches SDL3 and SDL3_net, builds them from source with the adapters, and links
`nocturne`. CI runs all of it under the `ci` preset, which is `coverage` and `game` together.

## `scripts/`

`scripts/Bash/` — the day-to-day loop:

| Script | Purpose |
|---|---|
| `prepare_keep.sh` | Create a `.keep` from the raw output with the correct header. Always use this |
| `test_compilation.sh` | Compile one or more files standalone; also reports unused locals |
| `test_suspects.sh` | Run the source-side suspect detectors against a file |
| `dbg.sh` | Drive a gdb session in tmux — see [debugging.md](debugging.md) |
| `netplay_test.sh` | Two-instance netplay harness |
| `generate_keep_files.sh` | Bulk `.keep` preparation |
| `regen_struct_layout_checks.sh` | Regenerate the struct-layout assertions |

`scripts/Python/` — Ghidra automation (PyGhidra headless) and analysis: annotation import/export,
pseudocode export with suspect detection, report/SVG generation, hidden-function discovery,
function-boundary validation, the sibling-binary mapping pipeline, and the recreation scaffold
(`scaffold_recreation.py`).

## Build outputs

`build/<preset>/` per preset, each with a generated `run.sh` and `debug.sh`, and
`build/recreation/<preset>/` for the recreation. Build directories are gitignored.
