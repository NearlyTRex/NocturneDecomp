# Changelog: November 2026

## 2026-11-15
- **The sound device's "commitDeferredSettings" is EAX reverb** (`04-mp3_audio_system/sound_device.md`):
  `setReverb(volume, decay_time, damping)`, set per camera from 27 EAX 1.0 presets. nocedit's
  listener-orientation names for it are gone. BW adds a real `commitDeferredSettings` at slot
  0x18, passes listener values as `float`, and gives `allocateSample` a `CSampleInfo *`. The
  three BW sound vtables are typed.
- **EAX is documented** (`04-mp3_audio_system/eax.md`). The game always sends environment 0
  (GENERIC) with the chosen preset's volume, decay and damping. Its 27 presets are EAX 1.0's in
  enum order. A camera that uses the global fog also uses the set's default reverb. nocedit's
  `g_KSPROPSETID_DirectSound3DListener` was really `DSPROPSETID_VoiceManager`, which `setMode`
  sets to mode 1, and it is renamed. Five DirectSound and EAX GUIDs are now labelled and typed in
  all five programs, each found by its bytes. `headers/eax/eax1.h` is a 0BSD reference header written from the binaries. Creative's
  `eax.h` has no licence grant, so it is not included.
- **Fourteen BW functions changed signature**, found where callers clean up a different number
  of bytes than nocedit's prototype implies. Each was read from the asm and is typed in all
  three builds:
  - **Added in BW:** `CDoor_getMoveType` and `CHero_tryOpenNearbyDoor` take `ignore_lock` (skip
    the "door is locked" check; one `game.cpp` call passes 1). `CBoundingBox3D_isVisible` takes
    `skip_shadow_test`. `CWayPoint_isReachable` and `findNearestReachable` take `skip_path_check`
    (the distance test alone). `CTextureCache_setupTexture` takes the `SMRGLTextureBasic *` (its
    `count` is the index) and an `upload_mode`.
  - **bw1 and bw3 only:** `CLever_setState` takes `silent` (no lever sound, passed on to linked
    levers). `CPodFile_mountFromFile` takes the error-text buffer that `25-pod_archives` describes.
  - **Dropped in BW:** `CScript_loadScript`'s `skip_validation`, `CDemonMission_loadScript`'s
    `is_loading`, and the LZW `process` methods' `byte_count`. `processFromBuffer` reads through
    BW's own `CInStreamMemory`.
  - **Moved:** `CDemonActor_getWorldBoundingBox` returns its box through ESI (`__stack3_esi`), like
    the skeleton functions above.
  - bw3's `tryOpenNearbyDoor` is `004d3040`. The mapping had paired it with `CHero_doHeroAction`.
- **The last 51 blocked BW functions are named and typed** (36 / 37 / 38 rows). Each pairing was
  checked against nocedit's body and each prototype read from the asm. Fifty were right. The one
  wrong pairing was BW's `renderTransparent`: it is a `return 0` stub shared by the
  `renderTransparent` and `getCollisionType` slots of `CActorDestination`/`CFilmProjector`, so it
  is named `getCollisionType`, as in nocedit. Changes found:
  - **`CBitFont_wrapText` takes `indent_chars` and `indent_first_line`** in every BW build:
    wrapped lines reserve that many spaces' width, and the first line does too only when the flag
    is set.
  - **`CScript_validateSyntax` takes `min_error_line`**. Errors before that line are skipped.
  - **bw3's `CCharacter_igniteBone` takes `on_fire_time`**, stored to `CCharacter.on_fire_time`.
  - **The codec reads and writes through BW's own streams.** `CCodec_process` calls the source's
    `getChar` and the sink's `putChar`/`ungetChar`, with no byte budget. `processToBuffer` uses
    `COutStreamMemory`, and `processFiles` uses `CInStreamFile`/`COutStreamFile`.
  - **`CDemonCamera_computeVisibleFrustumBounds` returns through ESI** (`__stack_esi`).
  - **bw2's `CInventory_addItem` takes a fourth argument it never reads.** All 12 callers push
    it; bw1 and bw3 keep three.
  - **bw3's `CLevelLoader_show` ignores two of its four arguments**: it always uses 12 frames,
    picks one of 4 images with `rand() % 4`, and drops the `moon.kfm` step. bw3's `update` never
    reads its `text`, and bw3 has no `cleanup`.
  - **bw3's `CLevelLoader` is nocedit's 304-byte layout.** The instance sits 0x130 below the
    next static object, `g_CLevelLoaderPtr` holds its address, and every field `show`, `reset`
    and `update` touch is at nocedit's offset (`current_frame` 0x0 to `color` 0x124–0x12c).
    `CLevelLoader` was imported into bw3. `reset`, `show` and `update` are typed there, and so is
    `show` in bw1 and bw2. The pointer and instance are labelled in all three builds.
  - **Editor dialogs format into a stack buffer** (`showYesNoDialog`,
    `showYesAllNoCancelDialog`), and bw2's status messages set alpha 1.0 first.
  - **`CEditorTools_restoreScreen` takes no arguments** in BW, so it is plain `restoreScreen`.
  - bw1's `renderAlphaBlendedFace` started 0x20 bytes late in Ghidra (`004826a0`). Its entry is
    `00482680`, byte-identical to nocedit's prologue.
- **The signature check reads a later cleanup**: Watcom often schedules a load between a call
  and its `ADD ESP,n`. The check now finds that cleanup, but only to confirm a size, never to
  convict. It confirmed about 200 more prototypes per build. On known-wrong pairs it confirmed
  none (0 of 42).
- **105 / 106 / 122 more BW functions are named** (bw1 / bw2 / bw3) from the mapper's pairs below
  the 0.9 gate. Each of the 413 rows was read against nocedit's body: 341 were right, 69 wrong and

    `getThrowDirection`, `computeWeaponAttachXForm` (`__stack3_esi`), and the vector helpers
    `subtractVector`, `addVector`, `evaluateSplineTangent3D`, `convertCubeIndexToPosition`.
    nocedit passes the output pointer on the stack.
  - **`CPod_mount` reports instead of quitting**: it takes `out_error_message`, copies the
    localized "Out of memory" or "Too many PODs already mounted" there and returns 0, or 1 on
    success.
  - **`CTextureCache_freeTextures` is the same function rewritten**: plain `free` instead of
    `debugFree`, a fourth true-colour buffer per entry, a `memset` of the table and an
    external-renderer callback. An earlier review had rejected the pair for sharing no callee.
  - **The quaternion/Euler conversions are closed-form** in BW (half-angle sin/cos), not built
    through a matrix.
  - **BW's `selectTextureBGRA` slot is `updateTextureFromPalette`**; BW has no BGRA select.
  - **Shared stubs stay unnamed**: one `xor eax,eax; ret` fills about 845 vtable slots in bw1,
    including `getGroundType`, and one bare `ret` fills `pickup`, `onDropped` and `drop`.
- **Wrong BW names fixed**:
  - The four `ckptutil.c` line helpers carried their neighbours' names (bw1 and bw3 two, bw2 one).
    The getters read the blending (bss) and clipping (data) globals in nocedit's order:
    `isLineBlendingDisabled`, `isLineClippingDisabled`, `setLineBlendingDisabled`,

  - bw1's `renderGogglesView` was its monster-vision variant (it reads `monster_vision_actor`).
