# Minimal P-code Patching Implementation

This document describes the minimal P-code patching implementation for Ghidra 12.1 that allows injecting custom P-code via files or scripts.

## Implementation Status

**STATUS: COMPLETE** - A working implementation has been created that requires modifying only **one Java file** (`DecompileCallback.java`). No C++ changes needed.

### Features

- **Instruction-level patches**: `<address>.pcode` for single instructions
- **Function-level patches**: `func_<entry>.pcode` for entire functions
- **Export script**: `ExportFunctionPcode.java` exports a function's P-code for editing
- **Auto-loading**: Patches are loaded automatically when the decompiler requests P-code

## Quick Start

### 1. Apply the Patch to Ghidra Source

```bash
cd /path/to/ghidra-source
git apply /tmp/ghidra-source/pcode_patch_final.patch
```

### 2. Rebuild Ghidra

```bash
gradle buildGhidra
```

### 3. Create Patch Directory

```bash
mkdir -p ~/.ghidra_pcode_patches
```

### 4. Create a Patch File

For an instruction at address `00510456`:

```bash
cat > ~/.ghidra_pcode_patches/00510456.pcode << 'EOF'
# Patch: Replace ESP-relative access with EBP-relative
# Original: MOV EAX, [ESP+0x20c]
# Fixed: MOV EAX, [EBP-0x8]

# P-code: TEMP = EBP + (-8)
INT_ADD (unique,0x1000,4) = (register,0x14,4), (const,0xfffffff8,4)

# P-code: EAX = LOAD [TEMP]
LOAD (register,0x0,4) = (const,0x1b1,4), (unique,0x1000,4)
EOF
```

### 5. Decompile

Re-decompile the function - the patched P-code will be used automatically.

### How P-code Flows in Ghidra

### Key Insight: P-code is NOT Stored

**Critical fact**: P-code is regenerated by the SLEIGH engine every time. It's not stored in the database. This means:

1. Patching must happen at **request time** when the decompiler asks for P-code
2. We need to store **patch definitions** in the database
3. At decompile time, check if a patch exists and return patched P-code instead

### Java Side Changes

#### 1. New Storage Class: PcodePatch

Store patch definitions in the program database.

```java
// New file: Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/pcode/PcodePatch.java

package ghidra.program.model.pcode;

import ghidra.program.model.address.Address;

/**
 * Represents a P-code patch for a specific instruction address.
 */
public class PcodePatch {
    private Address address;
    private PcodeOp[] patchedPcode;
    private boolean enabled;

    public PcodePatch(Address addr, PcodeOp[] pcode) {
        this.address = addr;
        this.patchedPcode = pcode;
        this.enabled = true;
    }

    public Address getAddress() { return address; }
    public PcodeOp[] getPatchedPcode() { return patchedPcode; }
    public boolean isEnabled() { return enabled; }
    public void setEnabled(boolean enabled) { this.enabled = enabled; }
}
```

#### 2. Patch Manager: PcodePatchManager

Manages all patches for a program.

```java
// New file: Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/pcode/PcodePatchManager.java

package ghidra.program.model.pcode;

import ghidra.program.model.address.Address;
import ghidra.program.model.listing.Program;
import java.util.HashMap;
import java.util.Map;

/**
 * Manages P-code patches for a program.
 * Patches are stored in program options/properties.
 */
public class PcodePatchManager {
    private Program program;
    private Map<Address, PcodePatch> patches;

    public PcodePatchManager(Program program) {
        this.program = program;
        this.patches = new HashMap<>();
        loadPatchesFromDatabase();
    }

    public void addPatch(Address addr, PcodeOp[] pcode) {
        PcodePatch patch = new PcodePatch(addr, pcode);
        patches.put(addr, patch);
        savePatchToDatabase(patch);
    }

    public void removePatch(Address addr) {
        patches.remove(addr);
        removePatchFromDatabase(addr);
    }

    public PcodePatch getPatch(Address addr) {
        return patches.get(addr);
    }

        PcodePatch patch = patches.get(addr);
        return patch != null && patch.isEnabled();

    public PcodeOp[] getPatchedPcode(Address addr) {
        PcodePatch patch = patches.get(addr);
        if (patch != null && patch.isEnabled()) {
            return patch.getPatchedPcode();
        }
        return null;
```

#### 3. Modify DecompileProcess

The decompiler communicates with Ghidra via `DecompileProcess`. We need to intercept P-code requests.

```java
// Modified: Ghidra/Features/Decompiler/src/main/java/ghidra/app/decompiler/DecompileProcess.java

// In the method that handles P-code requests from the C++ decompiler:

private void handlePcodeRequest(Address addr) {
    // Check if we have a patch for this address
    PcodePatchManager patchMgr = getPatchManager();
    if (patchMgr.hasPatch(addr)) {
        // Return patched P-code
        PcodeOp[] patched = patchMgr.getPatchedPcode(addr);
        sendPcodeResponse(patched);
    } else {
        // Return normal P-code from instruction
        Instruction instr = program.getListing().getInstructionAt(addr);
        PcodeOp[] pcode = instr.getPcode();
        sendPcodeResponse(pcode);
    }
}
```

#### 4. Add Instruction.patchPcode() Method

For script convenience, add a method to Instruction.

```java
// Modified: Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/Instruction.java

public interface Instruction extends CodeUnit, ProcessorContext, InstructionContext {
    // ... existing methods ...

    /**
     * Patch the P-code for this instruction.
     * The patched P-code will be used by the decompiler instead of SLEIGH-generated P-code.
     *
     * @param pcode The new P-code operations for this instruction
     */
    void patchPcode(PcodeOp[] pcode);

    /**
     * Remove any P-code patch for this instruction.
     */
    void clearPcodePatch();

    /**
     * Check if this instruction has a P-code patch.
     */
    boolean hasPcodePatch();
}

// Implementation in InstructionDB.java:
public void patchPcode(PcodeOp[] pcode) {
    PcodePatchManager mgr = program.getPcodePatchManager();
    mgr.addPatch(this.getAddress(), pcode);
}
```

## Minimal Script API

Once implemented, scripts could use it like this:

```python
# Ghidra Python script to patch P-code

from ghidra.program.model.pcode import PcodeOp, Varnode
from ghidra.program.model.address import AddressSpace

def patch_esp_to_ebp(addr):
    """
    Patch an ESP-relative load to use EBP instead.
    Original: MOV EAX, [ESP+0x20c]
    Patched:  MOV EAX, [EBP-0x8]
    """
    instr = getInstructionAt(addr)

    # Build patched P-code
    reg_space = currentProgram.getAddressFactory().getRegisterSpace()
    ram_space = currentProgram.getAddressFactory().getDefaultAddressSpace()
    unique_space = currentProgram.getAddressFactory().getUniqueSpace()

    # Varnodes
    EAX = Varnode(reg_space.getAddress(0), 4)
    EBP = Varnode(reg_space.getAddress(0x14), 4)
    CONST_NEG8 = Varnode(ram_space.getAddress(0xFFFFFFF8), 4)
    TEMP = Varnode(unique_space.getAddress(0x1000), 4)

    # P-code ops:
    # TEMP = INT_ADD EBP, -8
    # EAX = LOAD [TEMP]
    op1 = PcodeOp(addr, 0, PcodeOp.INT_ADD)
    op1.setOutput(TEMP)
    op1.setInput(EBP, 0)
    op1.setInput(CONST_NEG8, 1)

    op2 = PcodeOp(addr, 1, PcodeOp.LOAD)
    op2.setOutput(EAX)
    op2.setInput(TEMP, 0)

    # Apply patch
    instr.patchPcode([op1, op2])

    print(f"Patched instruction at {addr}")

# Usage
patch_esp_to_ebp(toAddr(0x00510456))
```

## Alternative: Simpler Approach

If the full implementation is too complex, a simpler approach:

### Byte Overlay

Instead of patching P-code, patch the **bytes** that SLEIGH sees:

```java
// Create a "virtual" instruction at the address
// Override the bytes returned to the decompiler

public class ByteOverlay {
    private Map<Address, byte[]> overlays;

    public byte[] getBytes(Address addr, int length) {
        if (overlays.containsKey(addr)) {
            return overlays.get(addr);
        }
        return program.getMemory().getBytes(addr, length);
    }
}
```

This would require less C++ changes but gives less control than P-code patching.

## Actual Implementation (Simpler Approach)

The original plan above was too complex. The actual implementation modifies only `DecompileCallback.java` and requires no C++ changes.

### Why This Works

The key insight is that `DecompileCallback.getPcode()` is called by the Java-side IPC handler **before** sending P-code to the C++ decompiler. By intercepting here, we can return patched P-code without touching C++ at all.

### Changes to DecompileCallback.java

The patch adds:

1. **Static patch cache**: `Map<String, PcodeOp[]> pcodePatchCache`
2. **Patch directory**: `~/.ghidra_pcode_patches/` (configurable via `-Dghidra.pcode.patch.dir`)
3. **File parsing**: Reads `.pcode` files with simple text format
4. **Interception**: Checks for patch before normal SLEIGH P-code generation

### Patch File Format Reference

```
# Comments start with #
# Blank lines are ignored

# Format: OPCODE (output) = (input1), (input2), ...
# Varnode format: (space, offset, size)

# Spaces:
#   register - CPU registers
#   const    - Constant values
#   unique   - Temporary variables
#   ram      - Memory
#   stack    - Stack space

# x86 Register Offsets (32-bit):
#   EAX = 0x0    ECX = 0x4    EDX = 0x8    EBX = 0xc
#   ESP = 0x10   EBP = 0x14   ESI = 0x18   EDI = 0x1c

# Example P-code operations:
INT_ADD (unique,0x1000,4) = (register,0x14,4), (const,0xfffffff8,4)
LOAD (register,0x0,4) = (const,0x1b1,4), (unique,0x1000,4)
COPY (register,0x0,4) = (register,0x14,4)
STORE (const,0x1b1,4), (unique,0x1000,4), (register,0x0,4)
```

| Category | Opcodes |

### Example: Fixing BADSPACEBASE

For an instruction `MOV EAX, [ESP+0x20c]` at `0x00510456` that should be `MOV EAX, [EBP-0x8]`:

**File: `~/.ghidra_pcode_patches/00510456.pcode`**

```
# Fix BADSPACEBASE: Convert ESP+0x20c to EBP-0x8
#
# Original instruction: MOV EAX, dword ptr [ESP + 0x20c]
# Problem: ESP tracking lost after indirect call
# Fix: Use EBP-8 (correct frame-relative offset)

# Step 1: Calculate address: TEMP = EBP + (-8)
INT_ADD (unique,0x10000,4) = (register,0x14,4), (const,0xfffffff8,4)

# Step 2: Load from calculated address into EAX
# Note: First input is space ID (0x1b1 = ram space), second is address
LOAD (register,0x0,4) = (const,0x1b1,4), (unique,0x10000,4)
```

### Determining Correct Offsets

To fix BADSPACEBASE, you need to determine what the ESP offset **should** map to in EBP-relative terms:

1. Find the function prologue's stack frame setup
2. Note the `SUB ESP, N` value (frame size)
3. Calculate: `EBP_offset = ESP_offset - frame_size - 4`
4. Or: Debug the original binary to see actual values
